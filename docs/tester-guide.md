# 動作確認 担当者向け手順書

やることは3つだけです。ブランチやPRは見なくて大丈夫です。

## 1. 依頼を開く

- 確認してほしい依頼は、この一覧に並びます（ブックマークしてください）
  https://github.com/issues?q=org%3Aadvalay+is%3Aissue+is%3Aopen+label%3Aqa-request+sort%3Acreated-desc
- 同じものをボード形式で見たいときはこちら: https://github.com/users/advalay/projects/1
- 依頼Issueには「確認する環境」「テストアカウント」「確認項目の表」「期限」が書いてあります
- 分からない点は依頼Issueにコメントで質問してください（Slackではなく、Issueに残す）

## 2. 確認して、結果をコメントする

- 表の項目を上から順に、書いてある手順どおりに操作します
- 全項目が終わったら、依頼Issueに次の形でコメントします

```
## 結果報告
環境: iPhone 15 / iOS 18.6 / Safari
| # | 結果 | メモ |
|---|---|---|
| 1 | OK | |
| 2 | NG | #123 に起票 |
| 3 | OK | 文言が少し気になる（好み） |
```

- 「好み」の感想（もっとこうだと使いやすい、など）は歓迎です。バグIssueにはせず、この結果報告のメモ欄か、末尾に「気づき」としてまとめて書いてください

## 3. NGは1件ずつバグIssueにする

- 依頼Issueと同じリポで「New issue」→「バグ報告（QA）」テンプレを選びます
- 1つの不具合につき1つのIssue。まとめて書かない
- 必ず入れるもの: 再現手順（番号つき）・環境・期待した動き・実際の動き・スクショか動画・重大度
- 重大度の基準
  - **動かない**: 操作が完了しない、エラーが出る、データが消える・表示されない
  - **使いにくい**: 完了はするが迷う、押しにくい、分かりにくい、遅い
  - **好み**: 動くし迷わないが、自分ならこうする（→バグIssueにせず結果報告に書く）
- 起票したら、結果報告の表に `#番号` を書く

## 全部終わったら

- 結果報告のコメントを投稿したら、依頼Issueを **Close** してください（NGがあっても閉じてOK。修正は別で進みます）

## 困ったとき

- stgが開かない、アカウントで入れない → 依頼Issueにコメント（その項目は「未確認」と書く）
- 動画が大きくてGitHubに載らない → Google Driveに上げてリンクを貼る
- 本番環境には触らない。依頼に書かれたURL以外は開かなくて大丈夫です
